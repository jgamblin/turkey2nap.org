TL;DR

Every version of Thanksgiving Dinner since 1621 lets an unauthenticated attacker (a relative) send a crafted payload (a second helping) to /couch and achieve Remote Nap Execution. No user interaction is required. The user will, in fact, stop interacting.

There is no patch. Mitigations exist. Exploitation in the wild has been observed. Mass exploitation is expected Thursday, within 15 minutes of kickoff.

02Technical details

The Thanksgiving Dinner runtime copies incoming food into a fixed-size stomach buffer without checking the Serving-Size header. The buffer holds one plate. It was sized in 1621 and has never been reviewed. A second helping overflows it, overwrites the return address for "go help with the dishes," and control passes to the Recliner subsystem.

The vulnerable code path is reachable before the host's own application logic ("I should help with the dishes") gets a chance to run.

An SBOM was requested. The vendor provided Grandma's recipe card, last updated 1974. It lists "butter (some)."

Example exploit request:

POST /couch HTTP/1.1
Host: living-room.local
Content-Type: application/x-gravy
Serving-Size: 2
X-Forwarded-For: grandma
Transfer-Encoding: stuffed

{"helping": 2, "gravy": "yes", "rolls": 4, "pie": ["pumpkin", "pecan", "apple"]}

05Mitigations & patches

  • Stretchy Pants 8.5.12. Increases buffer size. Does not fix the root cause, and may encourage a third helping.
  • A 10-minute walk. Rate-limits incoming payloads. Highly effective. Nobody does it.
  • Volunteer for dish duty. Attack surface reduction. It is very hard to nap at the sink.
  • Coffee. Temporary workaround. Wears off in 40 minutes. Do not chain with pie.
  • WAF rule: deny if plate.count > 1 && pie.count > 0. Not recommended. Grandma will notice.

If you cannot patch, follow the guidance from the National Nap Security Centre: take yourself offline. Lie down. Close the blinds. Put your phone face down.
